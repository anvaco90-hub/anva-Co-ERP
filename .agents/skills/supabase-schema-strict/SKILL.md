---

# ขั้นตอนการทำงาน
1. อ่านไฟล์ `dev_schema.sql` ในรากโปรเจกต์เพื่อตรวจสอบชื่อตาราง ชนิดข้อมูล และ Foreign Key ที่แท้จริงก่อนเขียนโค้ดทุกครั้ง
2. ตรวจสอบนโยบาย Row Level Security (RLS) และเงื่อนไขสิทธิ์ผู้ใช้ในโฟลเดอร์ `supabase/`
3. ตรวจสอบการจัดการ Error จาก Supabase client และแสดงข้อความแจ้งเตือนผู้ใช้ที่ชัดเจนเมื่อบันทึกไม่สำเร็จ

# ข้อห้าม (Do not)
- ห้ามเดาชื่อตารางหรือชื่อคอลัมน์เองโดยไม่เปิดดู `dev_schema.sql`
- ห้ามเขียนคำสั่งลบหรือแก้ไขข้อมูลจำนวนมากโดยไม่มีเงื่อนไข `eq` หรือตัวกรองที่ชัดเจน
