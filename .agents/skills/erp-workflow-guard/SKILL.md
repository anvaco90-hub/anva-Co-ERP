# ขั้นตอนการทำงาน (Workflow)
1. **ตรวจความเชื่อมโยงข้ามโมดูล:** ก่อนแก้ไขหน้าจอหรือ Query ให้ตรวจสอบผลกระทบต่อโมดูลที่เกี่ยวข้องเสมอ (เช่น การรับของ RI กระทบยอดสต็อกคงเหลือ รายการใน PO/PR และยอดงบประมาณโครงการ)
2. **ตรวจโครงสร้าง Supabase:** ยืนยันชื่อตาราง คอลัมน์ ความสัมพันธ์ Foreign Key และนโยบาย RLS ก่อนเขียนโค้ดดึงหรือบันทึกข้อมูล
3. **รักษาโครงสร้างหน้าจอและสถานะ:** ใช้รูปแบบการจัดการสถานะเอกสาร (เช่น Draft, Pending, Approved, Completed) และสไตล์ Tailwind CSS ให้สอดคล้องกับคอมโพเนนต์เดิมใน `src/`

# ข้อห้าม (Do not)
- ห้ามเดาชื่อตารางหรือชื่อคอลัมน์ใน Supabase โดยไม่ตรวจสอบจากไฟล์ในโปรเจกต์ก่อน
- ห้ามข้ามการอัปเดตยอดคงเหลือหรือสถานะเอกสารต้นทาง (เช่น PO/PR) เมื่อมีการบันทึกรายการรับของ (RI)
- ห้ามเปลี่ยนแปลงโครงสร้าง routing หรือ state หลักของระบบโดยไม่แจ้งผลกระทบต่อหน้าอื่น
